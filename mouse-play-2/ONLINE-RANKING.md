# 온라인 순위 연결 준비 — 현재 미연결

이번 버전은 요구사항의 대체 동작인 로컬 기록을 구현했습니다. 결과 화면에 「이 브라우저의 기록 · 온라인 순위 미연결」이라고 표시합니다. 온라인 순위 서버, 제출 API, 온라인 오류 복구는 아직 구현하거나 검증하지 않았습니다.

## 검토한 방안

Supabase의 무료 요금제와 PostgreSQL 데이터베이스를 활용할 수 있습니다. 공식 요금 문서에 무료 요금제가 안내되어 있으나 실제 가입 시 한도와 정책을 다시 확인해야 합니다. 무료 한도 안에서 영구 무중단 운영된다고 보장할 수는 없습니다.

- [공식 요금 안내](https://supabase.com/docs/guides/platform/billing-on-supabase)
- [데이터 접근 보호](https://supabase.com/docs/guides/database/secure-data)
- [행 단위 접근 권한](https://supabase.com/docs/guides/database/postgres/row-level-security)
- [API 키 안내](https://supabase.com/docs/guides/getting-started/api-keys)

## 실제 연결에 필요한 작업

1. 운영자가 Supabase 계정과 프로젝트를 생성하고 이용 조건을 확인합니다.
2. 날짜(한국 시간), 게임 ID, 난이도, 이름, 최고 점수로 기록 테이블을 만듭니다. `(day, game, level, name)`에 고유 제약을 걸어 중복 제출을 합칩니다.
3. 테이블의 행 단위 접근 제어(RLS)를 활성화합니다. 브라우저가 테이블에 직접 자유롭게 쓰거나 수정·삭제하지 못하도록 합니다.
4. 서버 함수에서 점수 제출과 순위 조회를 처리합니다. 비밀 키는 서버 환경 변수로만 저장합니다. 관리자 키를 HTML, JavaScript 또는 GitHub 저장소에 넣지 않습니다.
5. 브라우저에는 이름 입력 외에 가입 화면을 만들지 않고 서버에서 단기 게임 세션을 발급합니다. 시작 시각과 게임 종류를 세션에 묶고, 제출 시 150초 경과·일회성 제출·정수 점수·10/50점 단위를 검증합니다. 날짜는 서버가 결정합니다.
6. 세션 발급과 제출의 과도한 호출을 제한하고, 요청 크기와 허용 게임·난이도·이름 길이를 제한합니다. 동시 접속하는 교실의 공유 IP를 고려해 IP당 제한을 지나치게 낮게 잡지 않습니다. CORS만으로 보안이나 과도한 호출 방지를 해결할 수는 없습니다.
7. 브라우저에서 요청 시간 제한을 설정합니다. 제출 실패 시 로컬 저장을 유지하고 온라인 실패를 표시합니다. 서버 응답을 기다리느라 게임 시작과 종료를 막지 않습니다.
8. 두 컴퓨터의 동시 제출, 같은 이름의 최고 기록 경쟁, 한국 시간 자정, 서버 장애, 요청 제한을 실제로 테스트한 뒤 온라인 상태 표시를 활성화합니다.

이 문서는 설계 준비 자료이며 연결용 서버 코드가 포함된 것은 아닙니다. 이름만으로는 동명이인이나 타인의 이름 사용을 구분할 수 없습니다. 악의적인 점수 조작까지 막으려면 추가적인 서버 검증이 필요합니다. 온라인 공개 시에는 이름과 점수의 공개 범위·보관 기간을 운영자가 정해야 합니다.
